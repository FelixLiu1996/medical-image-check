# 发布规范初稿

## 发布渠道

- GitHub 公有仓库
- GitHub Release
- 语义化版本标签 `vMAJOR.MINOR.PATCH`

## 每个正式版本

- Windows x64 安装程序
- Windows x64 免安装压缩包
- 必要时提供独立模型包
- SHA-256 校验文件
- 变更说明
- 已知问题
- LICENSE、NOTICE/第三方声明
- 模型清单和算法兼容版本

## 自动化流程

1. 锁定依赖并执行许可证扫描。
2. 执行单元、集成和关键黄金数据测试。
3. 构建 CPU 基线发行物。
4. 验证 GPU 可用与不可用时的启动和回退。
5. 生成安装版、免安装版及校验值。
6. 执行干净 Windows 环境冒烟测试。
7. 发布 GitHub Release。

当前开发分支已实现 Windows/Linux 的 Ruff 和 pytest CI，并建立独立的 `Windows portable package` 工作流：

1. 安装锁定的运行、测试和 Nuitka 构建依赖。
2. 运行 Ruff 与 pytest。
3. 按 `pysidedeploy.spec` 构建 standalone 目录。
4. 运行打包程序 `--smoke-test`。
5. 收集项目许可证、第三方登记表及实际 wheel 的许可证文件。
6. 生成免安装 ZIP、SHA-256 文件并上传为保留 14 天的 Actions 工件。

该工作流目前由手动触发或 `v*` 标签触发，不自动创建 GitHub Release。Windows 安装程序尚未实现，免安装包仍需干净 Windows 10/11 人工验证后才能作为正式发行物。

## 发布限制

- 不包含真实实验数据。
- 不包含密钥、证书和本地路径。
- 不包含未完成许可证审查的模型或依赖。
- 第一版不要求自动更新。
- 商业代码签名暂缓；发布说明需要告知可能出现未知发布者提示。

## 回滚与兼容

- 保留可下载的历史正式版本。
- 数据格式升级前提供备份提示。
- 发布说明明确项目包、历史库和模型兼容范围。
