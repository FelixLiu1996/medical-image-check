# ADR-0013：大批量 Panel 按原始 Figure 对建立跨图 SIFT 候选短名单

- 状态：已接受
- 日期：2026-09-05

## 背景

`panel-split-4` 后，29 组同集阳性关系已有 21 组的两个自动拆分端点达到 IoU 0.50，逐关系只扫描两个自动裁剪时 matcher 命中 15/29，但按案例一次扫描全部 Panel 仅命中 14/29。差异来自 `eval-006-source-003-blue`：它在 258 个 Panel 的案例中具有 23 个共享哈希键，在对应两张原始 Figure 的候选中排第 5，但在全部 7,248 个小区域候选中排第 285，未进入全局 256 对主候选；单独扫描两个 Panel 时可以通过原有内容 verifier。

简单提高全局候选上限会同步放大所有高密度案例的计算量和误报审阅量。`panel-sift-fallback-1` 只在不超过 64 个 Panel 时启用，无法处理这类大批次候选竞争。

## 决策

1. 保留 `panel-sift-fallback-1` 对不超过 64 个 Panel 的既有行为，并将组合版本升级为 `panel-sift-fallback-2`。
2. 大于 64 个 Panel 时，只考虑至少共享 10 个分段感知哈希键的小区域候选。
3. 使用 Panel 临时文件到原始 Figure 的映射，按“原始 Figure A + 原始 Figure B”分组；只补充不同原始 Figure 之间的候选，同一 Figure 内继续走原有候选管线。
4. 每个原始 Figure 对最多保留哈希排名前 6 的候选，并以轮转方式组成最多 384 对的 SIFT 排序短名单，避免单个 Figure 对独占计算量。
5. 每侧最多使用 384 个 SIFT 描述子；至少 4 个比率匹配后才可进入最终补充集合。补充集合仍最多 64 对、每个 Panel 最多 8 对，最终是否报告继续由原有几何或小区域内容 verifier 决定。
6. 不放宽最终重复判断阈值，也不改变拆分边界、医学类型路由和展示层每规则/来源对最多 3 条的预算。

## 理由

- 问题是全局候选排序对跨 Figure 关系不公平，而不是最终 matcher 阈值过严。
- 在每个原始 Figure 对内先保留少量候选，再用 SIFT 排序，可以恢复被高密度同类 Panel 挤掉的跨图关系，同时维持明确上限。
- 同一 Figure 的标签、泳道和版式更容易产生高 SIFT 分数；不为同图额外开通这条补充路径，可减少无关 Western 行被加入审阅队列。

## 后果

- 17 个阳性案例、950 个自动 Panel 的按案例扫描由 14/29 提升为 15/29（召回 0.5172），只新增 `eval-006-source-003-blue`，没有丢失原 14 组；总结果 108 条，总耗时约 156.24 秒。逐关系 matcher 仍为 15/29，说明逐对和批量口径已对齐。
- 大批次补充前的主候选仍最多 512 个局部几何对和 256 个小区域对；两层补充各最多 64 对，因此 Panel 大批次 verifier 上限为局部 640 对、小区域 384 对，每个 Panel 在对应路径最多参与 32 对。
- 28 个已复核阴性案例的全量试验只新增 `eval-077` 同一 Figure 内的一条 Western 行候选，且没有新增 32 个医生确认误报区域模式。增加“只补充跨 Figure”约束后，`eval-077` 定向重跑恢复原 17 条；由于新路径相对旧版只增加候选、该约束只删除唯一新增项，最终 28 案例结果集合保持原 328 条。
- 该批样本直接参与候选策略选择，只能作为同集 validation/regression；不能据此报告独立 Precision、F1 或上线达标。
