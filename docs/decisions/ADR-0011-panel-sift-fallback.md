# ADR-0011：小批量 Panel 使用有界 SIFT 候选补充

- 状态：已接受
- 日期：2026-09-05

## 背景

`panel-split-3` 的 29 组已确认关系中，自动裁剪逐对运行可命中 13 组；按真实案例一次扫描全部 Panel 时，复核后的批量口径实际命中 11 组。差异集中在 `eval-012-source-005-green` 和 `eval-032-source-001-red`：两组都能通过小区域 SIFT 几何验证，但只共享 4/6 个分段感知哈希键，未进入原有 64 对补充候选。单纯扩大所有批次的候选预算会重新放大耗时和误报审阅量。

## 决策

1. 只在启用 Panel 拆分且解码特征不超过 64 个时，对原有低门槛哈希候选增加 SIFT 排序补充。
2. 每个候选两侧最多使用 384 个 SIFT 描述子，并同时检查原方向和水平镜像；至少 4 个比率匹配才进入排序。
3. SIFT 补充仍沿用全局最多 64 对、每个 Panel 最多 8 对的候选预算；最终是否报告继续由原有几何、内容和布局验证决定。
4. 超过 64 个特征的大案例保持原路径，避免在密集 Figure 上进行无界两两 SIFT 比较。
5. 该策略只修复候选生成，不修改医生 Panel 标注、自动拆分框或最终匹配阈值。

## 理由

- 两个已知漏检均有强 SIFT 几何证据，但分段感知哈希对局部裁剪、标签和边框变化不够稳定。
- 将较重的排序限制在最多 64 个特征，并保留原候选预算，可在召回收益和 CPU 耗时之间维持明确边界。
- 用最终 verifier 继续把关，避免把“进入候选”直接等同于重复结论。

## 后果

- 算法版本增加 `panel-sift-fallback-1`。
- 同集 29 组关系的真实按案例批量命中由 11/29 提升为 13/29，没有丢失原命中；17 个阳性案例总耗时由约 134.97 秒增加到约 143.86 秒。
- 5 个会触发该路径的已复核阴性小案例，结果数依次为 `0、6、2、9、6`，未产生新的 Finding ID，且 32 个医生已确认误报 ID 均未重现。
- 这批样本直接用于诊断和规则选择，只能作为 validation/regression；不能据此报告独立 Precision、F1 或上线达标。
