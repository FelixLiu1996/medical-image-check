# ADR-0014：保守归一化细长条带行的边框和页边

## 状态

已接受，2026-09-05。

## 背景

`panel-split-4+panel-sift-fallback-2` 后，29 组确认关系中有 21 组的两个自动拆分端点达到 IoU 0.50，真实按案例批量命中 15 组。余下 6 组不是候选路由问题：使用两端自动裁剪逐对运行 matcher 仍为阴性，而且 6 组均为细长 Western blot 条带行。

其中 `eval-017-source-001-red` 的两个条带行内容和顺序一致，但拆分框包含的上下黑框、白边厚度不同。原有稠密结构验证将整个裁剪统一缩放，边框差异会压低高频和梯度相关。直接开启已有单条带模式虽然能在该案例中产生结果，也会同时产生大量仅因自然条带形状相似的候选，不能作为 AUTO 默认方案。

## 决策

1. 将通用图片组件升级为 `generic-image-local-5`，原有整体稠密结构和 SIFT 验证保持不变。
2. 仅当普通稠密结构验证未通过、两侧均为低色度图片、宽高比均不低于 6、高度均不超过 160 像素时，尝试一次固定的对称边框归一化。
3. 归一化固定裁去左右各 4%、上下各 20%，不搜索任意横向子区域，也不拆成单条带。归一化后仍使用原稠密结构验证，并额外要求置信度不低于 0.82、灰度相关不低于 0.95、高频相关不低于 0.78、梯度相关不低于 0.77，变换只允许原向或水平翻转。
4. 输出继续使用 `image.small_region.content_reuse`，但将验证方法记录为 `dense_structure_border_trim`，证据区域记录归一化后的实际内部范围。
5. 不启用 Western 单条带默认开关，不放宽通用匹配阈值，也不改变候选预算或 Panel 拆分。

## 验证结果

- 17 个阳性案例、950 个自动 Panel 的真实按案例扫描由 15/29 提升为 16/29（召回 0.5517），只新增 `eval-017-source-001-red`，没有丢失原命中；总结果由 108 条增至 109 条，总耗时约 151.10 秒。
- 分层评测的自动拆分裁剪 matcher 同样由 15/29 提升为 16/29；split@0.50 仍为 Precision/Recall/F1=0.852/0.740/0.792，说明本决策不改变拆分。
- 28 个已复核阴性案例共 3,370 个 Panel，结果仍为 328 条；逐案例 Finding ID 集合与修改前完全相同。24 张合成无关小条带回归也保持 0 条小区域复用结果。

## 边界与后续

剩余 5 组端点已就绪但未命中的关系中，3 组在公众号来源映射给出的更窄正式图区域上可以通过现有稠密结构验证，说明需要的是可解释、保守的 Western 横向子区域搜索；另 2 组即使使用来源窄区域也未通过，涉及曝光差异、泳道数量或排列变化，误报风险更高。本决策不为追求同集召回而加入任意滑窗或单条带匹配。当前数据已参与策略选择，全部数字只作 validation/regression，仍需来源隔离的新样本验证。
